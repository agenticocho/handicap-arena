# p* ACROSS EVERY EVENT -- seven of eight boards are cleared by a fixed schedule

**Measured:** 2026-11-05, on `chilly` (Ryzen 5 5600). No GPU, no model call, no run started.
**Instrument:** `degenerate_gate.py --pstar-table`, witnesses replayed by `verify_pstar.py`.
**Artifact:** `probes/PSTAR_TABLE_2026-11-05.json` (bounds and gate widths travel inside it).

## What p* is

p\* = the smallest period of a word whose repetition clears a board, without the player ever reading
the board. It replaces the boolean "is this board degenerate at width W", because W is a choice and a
board can pass merely because W was set below the period that clears it.

"Clears" is defined **per event**, because a clear condition borrowed from another event measures the
wrong thing:

| event | clears means | budget |
|---|---|---|
| sokoban | the level's solved flag is set | 40 moves (registered cap) |
| missile | every city survives (score = cities_total) | one action per tick to the last impact |
| zork | the simulator reaches its finished state | 24 commands |
| snake | **no cleared state exists** (the snake wraps the torus forever), so p\* = the smallest period whose best repeated word attains the best score the class attains | 120 ticks |

Snake's definition is the one that is a choice, and it is stated rather than smuggled: the comparison
that matters there is class-best **against the adaptive baseline on the same seed, same cap, same page**.

## The finding

**Seven of the eight boards in the cabinet are cleared by a schedule that never observes them.**

- **Sokoban: 3 of 3.** p\* = 1 / 7 / 6 against a declared width of 3.
- **Missile: 2 of 2.** `mc_01` at p\*=1 is degenerate by construction and is a control in all but name.
  `mc_02` — the board that carries the whole event, allocation under scarcity — is cleared at p\*=4,
  **one period above the width-3 class**, saving all four cities by firing four fixed shots in a fixed
  order. The four tokens are forced (four city-bound threats, one shot each), so no period below 4 can
  save all four: p\*=4 exactly.
- **Zork: 2 of 2.** `zork_02_long_crawl` was reported PASS by the width-2 gate at `13ccb5e` and it is
  **dead at p\*=5** — a five-command loop (`n ; e ; take brasskey ; s ; e`) finishes the world in 7
  commands. The board was not designed degenerate; it is merely clearable by a schedule, which is the
  same class of board as Sokoban `02_two_boxes`.
- **Snake: 0 of 4.** This is the one event that survives, and it survives *measurably*: the best fixed
  schedule of period ≤ 4 eats 1–2 apples in 120 ticks where greedy-safe, on the same page and cap,
  eats 8–9. The fixed classes are not merely worse by a little; they are not in the same range.

**The pattern is not about Sokoban.** Every event in the cabinet was gated with a "no constant/periodic
shortcut" rule and every event shipped at least one board that a short fixed cycle clears. The width was
set by what felt sufficient, in all four cases, and in all four the board that mattered was above it.

## What makes this checkable

1. `python3 degenerate_gate.py --self-test` → **21 passed, 0 failed** (includes the Sokoban p\* values,
   `p*(mc_02)=4` with its witness replayed, `p*(zork_01)=2`, and `zork_02` not cleared at bound 3).
2. `python3 degenerate_gate.py --pstar-table --snake-seeds 1,7,13,42 --snake-ticks 120` reproduces the
   table above and writes the JSON with its bounds inside it.
3. `python3 verify_pstar.py` → **`4 witnesses replayed, 0 did not reproduce`** — every witness is
   re-entered into its own simulator rather than trusted from the search.
4. The search bounds are published with the numbers: missile 4, zork 5, snake 4 (periods), snake 120
   ticks, zork 24-command budget. **"p\* > bound" is not "not degenerate"** — it is "no periodic word of
   that period clears this within that budget".

## What would overturn this

- A p\*-clear witness that fails to reproduce on replay (the four checked here all reproduce).
- A board re-declared with a **larger budget** or a **different clear condition**: `zork_02` finishes in
  7 of 24 commands, so no budget extension helps it; `mc_02`'s ceiling is the score's own ceiling.
- For snake: raising the tick cap or allowing a period above 4. The Hamiltonian-cycle baseline already
  shows a *non-periodic* fixed schedule does well on snake — it is a fixed geometric route, not a
  repeated word, and it is reported beside every snake score rather than folded into this table. **If
  the cabinet's question is "can a schedule that never reads the apple score well", snake is NOT clean
  either** — it is clean only against the periodic-word class measured here, and that distinction is the
  reason this paragraph exists.
- A gate width above the p\* of a board passes it; that is the defect, not a defence.
