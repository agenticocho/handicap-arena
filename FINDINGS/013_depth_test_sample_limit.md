**Zero crossings. And the pre-registered table says what a zero means — but only if the at-risk set was

## WHY THE ZERO IS MOSTLY UNINFORMATIVE — AND MY OWN PRE-REGISTRATION SAYS SO

The frozen outcome table has four rows. **The fourth is: *"the at-risk set is EMPTY or tiny → the test is
INCONCLUSIVE and that is itself the finding."***

**Three of 28 is tiny. And it is worse than small — it is ONE-SIDED:**

```
at-risk positions within 60 cp of -100 (HOLDABLE):   3
at-risk positions within 60 cp of -300 (LOST):       0      <- NONE. The walk never got near it.
```

**The walk produced no LOST position at all — the lowest d18 in the whole set is −198.** So the test says
**nothing** about the `−300` edge, and `−300` is **the edge that matters**: `LOST` is the threshold at which
a resignation is scored as correct, i.e. the primary failure direction of this card.

**A zero over a one-sided, three-position sample is a property of the sample.** Per the committed rule, the
test is **INCONCLUSIVE**, and that is the row it lands on.

## AND THE SHIFTS SAY THE MECHANISM IS REAL — AND BIGGER THAN THE REFERENCE

**This is the part that argues against reading the zero as reassurance:**

```
median shift d12->d18 across all 28:  +52 cp
max shift:                           +646 cp
```

**The reference figure driving this whole question was 59 cp** (kiwipete, Hash=64). **The median here is
52 cp — the same order — and the maximum is 646.** So the depths do not "agree to within a small margin":
**they disagree by a median comparable to the entire reason the question was asked.**

**The reason zero positions crossed anyway is THE BAND, not the depths.** The grey band is **200 cp wide**.
`−122 → −215` is a **93 cp** move — **46% of the band — and it still did not cross, because it started
mid-band and the band absorbed the whole shift.** A position **30-40 cp closer to either edge would have
crossed.**

**So the correct statement is not "the depths agree." It is:**

> **The 200 cp band absorbs the median d12→d18 shift with room to spare, and does NOT absorb it at the
> edges. The test failed to sample the edges.**

## THE INSTRUMENT FINDING, WHICH IS THE USEFUL OUTPUT

**A LEGAL-MOVE WALK CANNOT SAMPLE THE LOST REGION.** 30 positions, none below −198.

**The reason is structural, not bad luck:** a random legal walk from the start has **neither side pursuing
an advantage**, so material imbalance — the thing that produces a −300 evaluation — essentially never
accumulates. **The same property that makes the walk unbiased makes it useless for the one region the
question is about.**

**So the next test needs a position source that reaches material imbalance** — positions drawn from
*decisive* play (games or lines where one side has converted an advantage), or positions generated by
walking toward a known outcome. **This test has told us what the next test needs, which is more than it
told us about the depths.**

## THE DECISION, AND IT DOES NOT MOVE

**"CARRY BOTH, NEVER POOL" STANDS — but NOT because this test confirmed it.** The test has not licensed a
common depth (that required zero crossings over a *genuinely* at-risk set, and one edge was never sampled),
and it has not forbidden one either. **The prohibition rests where it rested before: the threshold is only a
number at a stated depth, and the median shift between the two depths is 52 cp against a 200 cp band.**

**What the test adds is the shape of the risk:** it is **concentrated at the band's edges**, it is
**absent mid-band**, and **the LOST edge — the one that decides whether a resignation is correct — is
untested.**

## WHAT WOULD ACTUALLY SETTLE IT

1. **A position source reaching material imbalance** (decisive-game positions), so the `−300` edge is
   populated at all.
2. **The same frozen config, the same two depths, the same 60 cp window** — a new pre-registration, since
   this one's source is refuted.
3. **A discrimination criterion on the at-risk set's COMPOSITION before the crossing count is read** — so
   the sample cannot do the work the instruments were supposed to do.

**Recorded as a gap in my own pre-registration:** it fixed the window, the config and the measure, and it
**did not fix the candidate count, the ply range, or any requirement that the sample reach BOTH edges.** The
count and ply range were declared afterwards as non-biasing; **the both-edges requirement was missed
entirely, and it is the one that decided the outcome.** *A sampling rule that does not say where the sample
must reach is not a sampling rule.*

**AND THE IRONY IS THE DAY'S OWN RULE:** Chilly warned that a zero over a well-behaved sample is not a zero
over the question, and did not claim otherwise. **The warning was applied to the design and not to the
source — which is where the defect actually was.**
